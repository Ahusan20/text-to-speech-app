# Deployment

## Free frontend - GitHub Pages

The public, zero-cost demo deploys automatically from `main` through GitHub Actions:

https://ahusan20.github.io/text-to-speech-app/

It uses the browser's built-in speech voices and stores speech history locally.
Browser speech supports playback and on-demand download, while native seeking is
available for server-generated audio. Supabase sign-in
and cloud favorites are enabled for this deployment through GitHub Actions variables.

To configure them for another repository:

1. Add the repository Actions variables `VITE_SUPABASE_URL` and
   `VITE_SUPABASE_ANON_KEY`. The URL and publishable/anon key are public client
   configuration; never use a service-role or secret key here.
2. Enable Email sign-in in Supabase and run [`supabase/schema.sql`](./supabase/schema.sql)
   in the Supabase SQL Editor to create the favorites and speech-history tables with
   their Row Level Security policies.
3. Push to `main` or run the Pages workflow manually to rebuild and deploy.

On GitHub Pages, recent speech history remains in browser storage because speech is
generated by the browser. Signed-in favorites sync through Supabase.

## Frontend - Vercel

1. Import this repository in Vercel.
2. Keep the repository root as the project root so Vercel can use the root `vercel.json`.
3. Configure the `VITE_API_BASE_URL` environment variable to the deployed API
   origin (for example, `https://vox-studio-api.vercel.app`).
4. Configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` only when enabling
   Supabase Auth and cloud sync.
5. Deploy. The Vercel build reads the repository config and produces `client/dist`.

The GitHub Pages workflow also receives `VITE_SUPABASE_URL` and
`VITE_SUPABASE_ANON_KEY` from repository Actions variables for sign-in and favorites.
It does not need `VITE_API_BASE_URL` for browser speech. Never put service-role,
Gemini, or TTS provider secrets in frontend environment variables.

## Backend - Render

Render's Free web service plan is available, but this account requires a card
verification step with a temporary $1 authorization. Use the Vercel backend below
when avoiding payment details is a requirement.

## Backend - Vercel Hobby

Create a separate Vercel project from this repository with `server` as its project
root. Vercel detects the Express app in `server.js`; deploy it on the Hobby plan,
which is $0/month and has included function usage limits. Exceeding Hobby limits can
pause deployments until the next billing cycle rather than creating usage charges.

Set `CORS_ORIGIN` to the deployed frontend origin (without a trailing slash), then
set `VITE_API_BASE_URL` in the frontend Vercel project to this backend's origin and
redeploy the frontend. The backend returns audio as a data URL when Supabase Storage
is not configured, so audio playback and download do not depend on serverless local
files. Configure Supabase Storage for durable public audio URLs if desired.

Optionally add `TTS_API_KEY` and `ELEVENLABS_VOICE_ID` if using ElevenLabs; this
provider may incur charges under its own pricing. Add `GEMINI_API_KEY` only after
confirming its current terms and billing; AI enhancement controls stay disabled
until this key is configured. Add `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and
`SUPABASE_STORAGE_BUCKET` for durable audio uploads. The legacy service-role JWT is
preferred for Storage uploads. Although `SUPABASE_SECRET_KEY` is sent using the
new API-key header, this project's Storage endpoint treated that request as
anonymous and rejected it under RLS, so it only falls back to inline audio.
Keep all backend credentials exclusively in Vercel's backend environment settings.
Windows Speech SAPI is only available for local Windows development. The deployed
backend uses Google TTS unless ElevenLabs is configured.

## Backend Environment Variables

```text
PORT=5000
CORS_ORIGIN=https://your-app.vercel.app
DAILY_TTS_LIMIT=10
ADMIN_API_KEY=generate-a-long-random-secret
```

Only add optional provider credentials after confirming their pricing and terms.

## Supabase setup (optional)

1. In Supabase, enable Email sign-in under Authentication providers.
2. Run [`supabase/schema.sql`](./supabase/schema.sql) in the SQL Editor. It creates
   the history and favorites tables, their per-user RLS policies, and the public
   speech-audio bucket used for generated audio URLs.
3. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to the frontend deployment.
   For GitHub Pages, add them as repository Actions variables; for Vercel, use the
   frontend project's environment variables.
4. For durable audio uploads, add `SUPABASE_URL`,
   `SUPABASE_SERVICE_ROLE_KEY`, and `SUPABASE_STORAGE_BUCKET=speech-audio` to the
   backend deployment. The new `SUPABASE_SECRET_KEY` alone is not sufficient for
   this project's Storage endpoint. Do not expose the service-role key to the browser.
